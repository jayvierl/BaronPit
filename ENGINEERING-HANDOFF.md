## What changed

| Area | Finding on the actual release | Implemented change |
|---|---|---|
| Feed, rooms, threads and search | Multiple versions of the main SELECT disagreed about author flair and visibility. A direct thread or child reply could expose content the feed hid. Hashtags and builds were filtered after limiting a global feed. | One permission-aware reader scopes the query before the limit. It enforces bidirectional blocks, viewer mutes, hidden rooms and ancestor visibility. Votes and reactions check an eligible target. Builds, author and hashtag views query their own matching records. |
| Mutation feedback | UI toggles could report success on a failed request. The thread screen could fetch the same conversation twice. | One typed client helper checks both HTTP status and the application result. Controls commit on confirmation and expose retryable failures. Text drafts survive rejected writes. Direct thread pages load one reply list. |
| Recent player data | Partial rank or match requests could replace a healthy result even after the original zero-match patch. Repeat names were described as confirmed duos. | Single-flight lookup, differentiated stale/error results, no incomplete overwrite and scoped identifiers for teammate links. The refreshed profile exposes all available recent matches and labels repeat teammates and unverified claims accurately. |
| Community statistics | Trending and room summaries transferred full match histories for champion counts. Several linked players meant several extra round trips on profile/settings pages. | PostgreSQL returns grouped champion totals. A daily spotlight selects a single eligible player. A shared row mapper consumes the rows already joined by each page. Independent reads run together. |
| Build and match integrity | Clients could still stamp arbitrary build patches and send extra JSON fields. Legacy cards already in storage predated the server-side stats repair. | Build publication validates the confirmed patch, champion and item catalogs. Each post kind stores only its declared fields. New game cards carry server-owned validation. Old cards rederive their numbers from an available recent Riot match or retain the discussion with a verification notice. |
| Account and write boundaries | An origin suffix could influence sign-in. Some link-preview bots could consume single-use links. Rate checks and legacy sessions needed concurrency and migration coverage. | Canonical email origin, explicit confirmation for token redemption, single-use atomic sessions, pseudonymous new accounts, private age declarations, versioned consent, durable rate windows and a common participation/protection guard. Suspended people can report, block and appeal. |
| Moderation and first contact | Public uploads were reachable at the storage provider before human review. A claimed Riot profile could be used as a verified-looking LFG identity. Urgent reviews and appeals needed separate access. | New native uploads are disabled. Historic media URLs are suppressed in the app. New supported external clip links require human review and open on the provider. Duo contact needs a verified link, recent rank, the same age band and a mutual request. Reviews have private outcomes, evidence-aware notices, independent appeals, urgent responders, two-person restricted release, and timed room raid controls. |
| Bootstrap, patch watch and rendering | Cold schema setup ran dozens of dependent network round trips. A missing cron secret allowed requests. A patch job could leave rooms missing their briefing. Root navigation fetched session data even for policy pages. | A revision check and one ordered, locked upgrade transaction. Daily cron fails closed and does maintenance. The patch job recovers missing briefings without duplicating existing ones. Static policy pages and hourly champion-directory regeneration keep session data out of public cache. |
| Mobile and delivery | Main actions were hard to discover on small screens. Remote fonts and a missing portrait could break polish during provider outages. | Accessible mobile Explore navigation, a working guest composer destination, a player search on Home, local licensed typefaces, and an official-patch fallback champion portrait sheet. No Blob upload library ships to readers. |

## Measurements and checks

- Fixture with 200 players and 20 matches apiece. The old trending query returned **1,711,801 bytes** of row JSON. The grouped query returned **66 bytes** for the same two champions and totals. This measures database results for that fixture. Real savings vary with the roster and sample.
- Signed-in feed with a poll. On identical seeded data, the old release made **8 database calls** and the rebuild made **4**. On 32 alternating warmed in-process runs per version, median query processing went from 4.81 to **5.71 ms**. Stricter visibility and richer flair raised row JSON from 10,479 to 10,769 bytes. Production latency has not been established.
- The original release’s **16 tests** passed before changes. The rebuild passed **88 automated tests** across 16 files, including real PostgreSQL semantics for policies and transactions, fresh and existing-schema setup, concurrent sign-in, privacy and appeals, and synthetic screening results. Lint and strict TypeScript checks passed. The Next production build completed. The shipping dependency lockfile returned zero known production advisories on the audit date.
- The actual production bundle passed **16 seeded HTTP journeys** with a local PostgreSQL transport. Those include signed-in reads and writes, feed and thread access, private and missing items, two browser-origin forms, and closed cron/upload routes. The smoke script binds to loopback, seeds inert fixture accounts, and does not contact real players, email or moderation providers.
- Chromium checks at 360 and 390 pixels covered 14 page/state combinations, keyboard navigation, user-visible failures, and champion filtering. No horizontal overflow was observed in those checks. This was viewport testing on Chromium, not a physical iPhone or Android test.
- Before the rebuild the public home, Zed room, builds, champions, LFG, sign-in and policy pages responded 200; the protected cron returned 401 and the retired lookup path returned 404. HTTP success by itself does not establish authenticated feature correctness. No real mail delivery, Riot-owned identity linking, native upload scan, on-call acknowledgement or external report was performed.

## Release and rollback

1. Use this source package in the `ward-party` project. Run the commands in [README](README.md) from its root. Use the correct Vercel team and recheck the existing production alias for work released by Muse since the audit.
2. Provision any intended preview database separately via `WARD_PREVIEW_DATABASE_URL`. A generic Vercel preview has no permission here to migrate the production database. Keep a rollback-capable Neon backup. Validate existing users, posts and current patch state before promotion.
3. Confirm the email origin and sender, private moderation staffing and pager rehearsals. Treat actual email delivery and responder acknowledgement as external acceptance checks. Leave `DUO_MATCHING_ENABLED` off pending RSO approval and an effective ownership-link flow. Decide any new telemetry or vendor spend with Jay.
4. Use [Duo and media operations](DUO-AND-MEDIA.md) for existing public Blob objects. Suppressing them in a new build cannot invalidate a previously known storage URL. Establish private custody and obtain authority for disposal where appropriate. Keep native submissions paused until authorized scanning and custody are operational.
5. After Jay approves the release, promote the tested build in the correct production environment. Smoke the branded alias, canonical signup email, an existing player lookup and a signed-in thread with approved test accounts. Watch user-visible errors, lobby availability, queue age and query timing. For an incident, pause participation and address existing material. The previous live build lacks several new safety controls; consider those risks before rolling code back. Keep any newer safety evidence and decisions when recovering service.

## Open external decisions

Riot production approval and RSO credentials, incident staffing, the legacy public-media inventory, provider-custody agreements, and any field analytics collection still need their respective owners. The release adds no paid service, public reputation score, gameplay archive or monetisation flow. See [Community safety operations](COMMUNITY-SAFETY.md) for thresholds, authorities and escalation.
