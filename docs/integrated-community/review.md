# Independent integration review

## Baseline

The review started on `ede1189`. Script-disabled Chromium at 390 CSS pixels rendered Search, a saved Riot player search, Builds, Champions and a discussion with HTTP 200 and no horizontal overflow. The player search still put its source PUUID into raw HTML because a client link used it as a React key. Search had five scopes covering people, rooms, posts and player stats. The build directory lacked a direct build submission action, and the discussion had reposting but no native quote action.

The public `/search` and `/builds` pages returned HTTP 200 from Vercel. A 320 CSS pixel axe scan across Search, Champions, one champion room, Builds, a player profile and a thread in both themes found three affected instances. The profile's “Ranks” link had an accessible name that omitted the visible word in both themes. The dark Builds empty-state “feed” link relied on color inside running text. All 12 baseline views fit the viewport.

## Candidate verification

- 44 targeted tests passed across quote publication, post and build reads, question progress, champion summaries, universal search and schema bootstrap. The live-style quote route tests use synthetic accounts and PGlite, exercise concurrent retries with one stored post, and check held posts, mute and both blocking relationships. Room holds, withdrawal and deletion remove source evidence. The same visibility conditions apply to search, metadata and the private library. [Quote fixtures](../../src/lib/quote-posts.test.ts) [Search fixtures](../../src/lib/community-search.test.ts)
- Build reconfirmation checks the author's currently visible post and its recorded items against a confirmed current shop. The positive fixture now contains an actual item. The test distinguishes an authorized reconfirmation from an unavailable build. [Build read tests](../../src/lib/post-reader.test.ts)

- Chromium passed 24 views at 320 CSS pixels in light and dark themes with zero WCAG-tagged axe violations and zero horizontal overflow. The sample covered search, champion and item results, the champion directory and hub tabs, builds, player profile, private progress and a thread. Four checks covered open quote and build editors in both themes. Both baseline accessibility findings cleared. Guest and signed-in search HTML excluded the previously exposed PUUID. Enter opened the quote editor, Escape closed it and restored focus to the trigger, and the editor reopened for a draft. The build action preserved the chosen champion. The private Progress filter worked from the keyboard and redirected a guest to sign-in. ## Artwork and feed rerun

With Data Dragon artwork blocked, the first optimized rerun found nine item links per theme whose accessible names omitted the visible fallback initials. The fix uses the same abbreviation for the icon and the item link while retaining the full item name. Fourteen focused tests and scoped lint passed. [Icon and item fallback test](../../src/components/room-artwork.test.ts)

The final optimized build `SZ8sBJB8f7cDt9rXpFk7u` passed all 28 Chromium views at 320 CSS pixels in light and dark themes, with zero WCAG-tagged axe violations or horizontal overflow. The sample included both Home tabs after the feed query change and both open editors. With Data Dragon artwork still blocked, the champion room loaded its same-origin banner fallback and named item results retained readable initials. The search, quote, build and private Progress keyboard journeys passed again. ## Evidence boundaries

The accessibility scan and keyboard checks cover the listed Chromium views. They do not establish complete screen-reader or cross-browser conformance. The champion overview describes observed appearances across supported public queues and mixed patches. The ranked record, recent match sample, archived rank and player-authored follow-up each have their own scope. The fixture uses synthetic matches and accounts. No production writes, live provider capacity, or real player outcomes were tested.
