# Baron Pit published-code audit

November 27, 2026. The baseline is the `ward-party` production deployment of `jayvierl/BaronPit` at `2ecce6d` on baronpit.com. This review covers the Next.js app, its API and database access paths, the published browser experience, and the locked dependencies. Production checks used public navigation. Account changes, posts, moderation decisions, and simulated Riot reads used disposable fixtures.

| Area | What went wrong | What the fix verifies |
|---|---|---|
| Sign-in and account safety | A guest could land on an eligibility form that required a session. Returning members were asked for an age group already on record. Temporary failures checking an email link could look like expiration. | Guests reach email sign-in with their return destination. Eligible members continue, and returning members can confirm current terms using their recorded age group. A valid link can be retried after a temporary failure. |
| Profile and moderation | A held account could pass ordinary write and staff gates. The safety inbox offered no direct way to remove an uploaded profile photo. Certain forms could submit sensitive text through the address bar before JavaScript loaded. | Held users retain protective actions. Private photo removal and terms acceptance verify which account opened the form. Staff access, ordinary edits, and form submission respect their distinct permissions. |
| Replies and reposts | Reopening replies could count the same reply twice. Withdrawing it could leave a count beside an empty thread. A stale editor could publish a reply under the account that most recently signed in. A quote repost could keep attributing a share after a block. | Counts follow the visible reply tree. Reads and submissions bind to the active viewer. A blocked share attribution disappears. |
| Player stats and match discussions | Transferred players' match details could be requested from the wrong region. Intentional public-queue exclusions could appear as incomplete data. A game discovered during refresh could be rejected as newer than its source. | Match IDs determine routing. Public sample size and completeness are labeled separately. The saved observation time supports discussion and timeline checks. Filters survive a trip to the timeline, and missing objective data has an explicit state. |
| Builds, search and navigation | A build thread could discard its item, champion, or off-meta search context. Compare collapsed items that share a display name but have different prices. A historical patch request could replace the active catalog fallback. With scripts disabled, the published Builds pages could show a loading message indefinitely. | The composer and list preserve their respective return paths. Distinct Riot item IDs remain selectable. The current fallback keeps its actual patch. Rendered builds are available without JavaScript, with pending feedback on client navigation. |
| Composing | On mobile, the global post link could leave the editor collapsed. On a champion's Builds tab it could stop at another link. | Keyboard, touch-width, and native fragment navigation reach the appropriate composer with champion context intact. |
| Duo Finder | Fall-back clock changes could make a real hour-long session appear to have zero duration. Invitation retries, expiry labels, and the shared contact window could disagree with saved state. The board also sent recurring availability that its cards did not display. | The agreed instant, time zones, expiry, and saved invitation state govern the UI. Matching can use permitted schedules without sending someone else's recurring availability to the viewer. |
| Scheduled publishing and pilot reporting | Patch briefings could publish through a safety pause. Held accounts' answers and replies below hidden ancestors could count toward pilot success. An unavailable host list silently disappeared. | The patch job catches up once after a pause. Metrics use the same visibility rules as conversations. The review-hour page distinguishes an empty list from a failed lookup. |

Static item data and the sign-in page still rendered. | Each affected route distinguishes an unavailable read from a confirmed missing destination. ## How to repeat the checks

The published build passed its original nine route checks while the guest eligibility and composer defects were still present. On the corrected optimized build, 237 HTTP fixture checks passed. Chromium verified the sign-in return, timeout and retry, account switching, and photo removal at a 390px viewport. A separate browser check disabled JavaScript and opened Builds, the item-seeded composer, and Compare. With JavaScript enabled and a deliberately delayed response, the build link displayed its pending state and arrived with the item selected. These checks used no production accounts.

Independent review caught three issues during repair. A link-check API was unavailable in older supported browsers, an item-origin composer had lost its direct return link, and a stale account tab could submit a private form for its new viewer. The final implementations use a compatible abort controller, keep item and list return paths distinct, and bind account-sensitive reads and edits to the viewer who opened them.

Use Node 22.12 or later and the committed lockfile. Run `npm ci`, `npm test`, `npm run lint`, `npm run build`, `npx tsc --noEmit --incremental false`, and `npm run smoke`. The smoke suite runs the optimized application against isolated data. The browser journeys are in `scripts/smoke/community-workflows-demo.mjs` and `scripts/smoke/match-discussion-demo.mjs`. Run `npm run check:release -- <origin>` against a deployment with the normal public rooms available.

No schema migration, data backfill, new service, or new production setting is needed for these fixes. The previous production deployment remains the rollback point. The fixtures exercise Riot responses and email-link handling independently of live provider delivery. Production identity verification, paid tips, and live uploads retain their existing deployment requirements.
