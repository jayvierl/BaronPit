# Independent match discussion audit

The baseline is `0cecdc0`. This audit checks the path from player lookup to a moderated match discussion, then through the Following feed, related hub, replies, saved discussions, and return links. The baseline findings describe the starting code. The candidate results below use a local build, Chromium and the existing synthetic PostgreSQL fixture.

## Acceptance checks

1. Find a public Riot match as a guest. Open a preview identifying the player perspective and the observed Riot source. Complete sign-in while preserving the intended draft and return links. Publishing an observer’s discussion requires the ordinary community account and publication checks. Verified Riot status applies only after the account’s current, uncontested ownership proof and never follows from a public lookup.
2. Use a fixture with different author and subject identities and a second, unrelated match. Check that server-derived context, queue, champion, patch, public name and selected item agree with the selected game. Verify that unknown fields are labeled as unavailable. Check the public HTML, generated URLs, JSON/client payloads, source links and previews for private identifiers, email and full roster details.
3. Verify a visible publish in the relevant hub and a separately authenticated viewer’s Following feed. Check tied timestamps and continuation while a new post appears. Save privately, reply and follow, and open the author’s activity link to the exact visible reply. Return to the stable post, original match if available, champion and player. Repeat after a snapshot refresh displaces the source game.
4. Exercise the same paths with a held, withdrawn, deleted, absent or custom source, blocked and muted viewers, and hidden author or room. Inspect the cache and notification effects, search, feed, saved and metadata surfaces. A disabled feature should expose a useful empty or unavailable state. A stale guest draft should preserve its text and clearly require a new source or explicit detach.
5. Validate samples against fixture arithmetic. A ranked-only sample includes queues 420 and 440. Win percentage uses known outcomes and an explicit denominator. Kill participation divides kills plus assists by observed team kills, and zero or unknown team kills produce no rate. CS/min uses actual game duration. A failed or partial provider response must not become a zero, a “live” claim, or a newly verified artifact. [Riot API reference](https://developer.riotgames.com/apis/)
6. Account for new external calls, concurrency, TTL, moderation and database work. Respect Riot’s published rate-limit handling and verify that no paid provider, deployment, approval, matchup advantage, or account ownership is inferred from a local fixture. [Riot rate-limit documentation](https://developer.riotgames.com/docs/portal) [Riot game integrity policy](https://developer.riotgames.com/docs/lol)

Baseline verification used the existing match history, public post, question, analytics, discussion library and personal safety suites. All 47 tests passed.

## Candidate verification

- **57 targeted tests passed across 11 suites.** The SQL fixture distinguishes the author and the Riot account, including verified ownership and spectator paths, tested unavailable and stale match context, and verified that forged fields cannot override the Riot snapshot. A recorded card stayed readable after its source game aged out. Blocking the verified source hid the discussion from the viewer across direct lookup, the related notebook and unfurl metadata. Existing reply, withdrawal, save, mute and visibility tests passed. Cursor tests passed for chronological Following, equal timestamps, impossible calendar dates and invalid cursors. [Decision tests](../../src/lib/decisions.test.ts) [Library tests](../../src/lib/discussion-library.test.ts) [Feed tests](../../src/lib/home-feed.test.ts)
- **The baseline draft privacy defect no longer reproduced.** In Chromium with scripts disabled, the plain and matched question editors exposed a native sign-in link and kept their submit controls disabled and unnamed. With 10 script requests held, no native submission left the attached editor. Once bundles loaded, the typed body stayed in browser storage behind an opaque draft key. The observed request URLs contained no draft text. On the follow-up build I injected a synthetic saved draft for an unavailable match and used the browser’s copy control to recover it. A separate link starts a new question without that attachment. [Composer](../../src/components/decision-composer.tsx) [Recovery](../../src/app/questions/new/page.tsx)
- **Confirmed HTTP and caching behavior.** The same-origin guest write returned `401`, a cross-origin authenticated write returned `403`, and unconfirmed, unavailable-match and legacy direct-card requests each returned `400`. A signed-in, unlinked fixture observer received `201`. Its public preview and post HTML contained no source PUUID or fixture account email. The post served `Cache-Control: private, no-cache, no-store, max-age=0, must-revalidate`. A player name changed in the return URL could not substitute for the resolved Riot ID. [Question route](../../src/app/api/questions/route.ts) [Post route](../../src/app/api/social/post/route.ts) [Return validation](../../src/lib/decisions-input.ts)
- **Profile arithmetic and scope.** In the 100-game synthetic player source the selected ranked win is 6/2/7 over 30 minutes with 120 CS and 20 team kills. That yields a 6.50 KDA, 4.0 CS/min and 65% kill participation. This arithmetic uses one game. Official ranked-year queue records are separate from the recent public sample. The branch uses seven reviewed queues and excludes custom, unknown and other unsupported modes from the public sample. [Profile fixture](../../scripts/smoke/profile-depth-fixture.mjs) [Queue policy](../../src/lib/public-match-queues.ts) [Riot queue catalog](https://static.developer.riotgames.com/docs/lol/queues.json)
- **The profile still leaked a source identifier on the first build.** Its client match-filter form used the PUUID as a React key. The updated build uses public lookup fields and omits the PUUID from raw HTML in four variants covering guest and signed-in access with and without filters. Chromium also confirmed the return link preserves the exact player, match, filter and older page while dropping unrelated query values. [Player profile](../../src/app/player/page.tsx) [Return validation](../../src/lib/decisions-input.ts)
- **The pilot distinguishes questions from perspectives.** The dedicated notebook, starter and related question workflows exclude perspectives from unanswered work. The internal reply metric describes currently visible questions submitted at least 24 hours ago and discloses that moderation time counts. Day-seven return is scoped to the separate opt-in ranked bot/support pilot. [Question selection](../../src/lib/decisions.ts) [Pilot dashboard](../../src/app/admin/pilot/page.tsx)

## Follow-up and limits

- Item attachment membership is verified against the selected match's recorded item IDs. Display labels use the available item catalog. This does not establish the item’s historical stats, purchase timing or build optimality. [Item validation](../../src/lib/decisions.ts)
- Published cards retain selected match facts, so the original exact match can disappear from the player's bounded history while the post remains. Personalized source blocking depends on a currently verified identity link. Account deletion still uses the site’s support process. [Public privacy notice](../../src/app/privacy/page.tsx) [Visibility conditions](../../src/lib/community-queries.ts)
- No production write, real email, live Riot ownership verification, or live capacity measurement was made in this audit. The reply and return fixtures demonstrate mechanics. They cannot establish helpful peer supply, retention, response time in production, or customer demand. [Demo scope](./demo.md)
