# Match discussion reference research

Checked November 27, 2026 UTC. The browser work used signed-out Chromium at 1,180 CSS pixels and at 400 CSS pixels. The narrow check used ordinary window resizing and page zoom. It establishes responsive web behavior. The iOS and Android observations below come from the products’ own documentation. The public OP.GG search used a professional player’s published Riot ID. The Threads example was a public League of Legends esports post.

**Observed** means the control or outcome was seen in the live browser. **Documented** means a product owner or Riot describes it. **Inferred** identifies an interpretation of that evidence. **Baron Pit decision** describes the proposed adaptation or cites the implementation under review.

## OP.GG

- **Observed · Find a player.** On the homepage, select the region, enter the full `GameName#TAG`, and submit. Changing NA to KR changed the tag hint. The public lookup opened the player’s profile on a URL containing the region and complete Riot ID. The profile showed a separate `Last updated` stamp and a queue and champion filter. The age of a listed match differed from the age of the profile’s last update. [OP.GG homepage](https://op.gg/) · [Observed player profile](https://op.gg/lol/summoners/kr/Hide%20on%20bush-KR1)
- **Observed · Inspect a match and return to the list.** The history rows show result, queue, duration, champion, score, items and compact team lists. Expanding one row added Overview, OP Score, Team analysis, Build and Etc. in place, at the same profile URL. Overview showed the teams’ scoreboards. Etc. exposed chart views for gold, experience and CS. At 400 CSS pixels the profile stacked its sections and expanding a second match still surfaced its detail tabs under the row. The expanded row state had no separate public permalink in this check. [Observed player profile](https://op.gg/lol/summoners/kr/Hide%20on%20bush-KR1)
- **Documented · Mobile, refresh and incomplete data.** OP.GG documents region and full Riot ID search on PC web, mobile web and its native apps. It documents a Riot-link shortcut to one’s own profile and private per-match notes for linked users. Its support guidance attributes some stale history to delayed upstream or internal processing and describes exclusions for particular modes or bot games. Its July 2025 support article says custom-game stats are unavailable on OP.GG. Treat that statement as OP.GG’s product behavior. The permission rule for Baron Pit comes from Riot. [Riot ID search](https://help.op.gg/hc/en-us/articles/31090336977177-How-to-search-stats-using-Riot-ID) · [Linked account features](https://help.op.gg/hc/en-us/articles/30993148799897-Features-available-when-linking-a-Riot-Account) · [Updating stats](https://help.op.gg/hc/en-us/articles/31088795082393-My-stats-aren-t-updating) · [Custom games](https://help.op.gg/hc/en-us/articles/31089445595033-I-want-to-view-my-stats-for-custom-games)
- **Documented · Separate esports surface.** OP.GG’s esports guide describes a completed-match detail page, VODs and timeline graphs. This is useful evidence for progressive disclosure on an esports product. The signed-out summoner walkthrough establishes only its own in-row tabs and charts. [OP.GG Esports match detail](https://help.op.gg/hc/en-us/articles/31091817743129-Viewing-detailed-match-data)

## Threads

- **Observed · Find, open and return.** The signed-out Home showed an invitation to sign in. The Search navigation worked. Submitting “League of Legends” briefly showed a loading indicator, then results. The esports result’s timestamp opened its own permalink. The thread displayed the original post, visible replies and a separate timestamp link for each reply. At the point where more replies were gated, the page showed an explicit login prompt. Share exposed Copy link while signed out. The thread’s Back button restored the same search query and results. Scroll restoration was outside this check. [Observed search](https://www.threads.com/search?q=League%20of%20Legends&serp_type=default) · [Observed public thread](https://www.threads.com/@lolesportstw/post/DQOV2ZFkrsi)
- **Observed · Narrow flow.** At 400 CSS pixels, Threads used a one-column view, a compact Back control and a dismissible sign-in sheet over the search results. Closing the sheet revealed the results. Opening the same post loaded the original and some replies, and Back returned to the same query with the search field focused. The thread still exposed a separate prompt to sign in for more replies. [Observed search](https://www.threads.com/search?q=League%20of%20Legends&serp_type=default) · [Observed public thread](https://www.threads.com/@lolesportstw/post/DQOV2ZFkrsi)
- **Documented · Audience, context and return.** Meta documents topic tags, keyword search, Following, hidden words and private-profile follower approval. The web guide covers saved and liked posts, pinned columns, and custom feeds in the same order as mobile. Meta’s reply controls announcement describes approved replies, filters, and follower-only reply or quote controls. These are vendor-documented capabilities. Account-only settings, composition, saved state and native app interaction were outside the signed-out browser check. Generic account linking proves ownership. A separate sharing decision governs publication. Riot’s general game-integrity rules also restrict identifying deliberately hidden players, live competitive advantages, and alternative skill rankings. Review temporary and unfamiliar queues before adding them to public coverage. The expansion request and any paid feature should describe the actual added value and user flow in the Developer Portal. ## Baron Pit adaptation and acceptance

**Inferred.** OP.GG’s in-place match drill-down and Threads’ durable conversation URLs solve different navigation problems. A player can study one game without leaving the filtered history, then share a discussion that opens at the exact match or reply. A compact evidence card lets a reader join the discussion without reconstructing the match from a screenshot. A viewer can infer the relevance of a recommendation from its room or recent discussion activity. [Observed OP.GG profile](https://op.gg/lol/summoners/kr/Hide%20on%20bush-KR1) · [Observed Threads conversation](https://www.threads.com/@lolesportstw/post/DQOV2ZFkrsi) · [Baron Pit feed rules](./feed.md)

| Baron Pit decision | Acceptance |
| --- | --- |
| **Match to discussion and back.** Open a real, eligible match from its player history or deep link. Offer a question or perspective with a reviewed evidence preview. Preserve the selected match, region and valid draft continuation across sign-in. Keep the discussion and match destinations independently addressable. | Guest can open a match and draft, then finish sign-in and return to the same context. A second account can open the published post from the feed or matchup hub, reply, and return via the link to the original match and scoreboard. Reload, Back and an exact Activity reply link each keep their intended target. Use keyboard and a 390–400 CSS pixel viewport. [Local reproducible walkthrough](./demo.md) |
| **Evidence and privacy.** Project from one eligible, recent server-validated snapshot. Use the real queue, champion, patch where known, match result, duration and scoreboard values. Label ownership only after uniquely verified account linkage. Newer or unsupported values remain unknown. Keep custom and unrecognized queues out of public previews, filters, rollups, roster links and historical attachments. | A forged match or a stale, custom, unrecognized, blocked, hidden or withdrawn source cannot publish through the new or legacy shapes. Public JSON and HTML omit private identifiers and custom data, including indirect counts or links. Unlink and contested ownership change the owner label at validation. A public evidence preview and explicit confirmation precede publication. [Context projection](../../src/lib/match-context.ts) · [Snapshot resolver](../../src/lib/question-match.ts) · [Public queue allowlist](../../src/lib/public-match-queues.ts) |
| **Conversation access and return.** Keep signed-out reading on the same page. Keep saves private. Reuse the existing block, mute, reports, visible-reply tree, and notifications. Explain why Discover surfaced a post using a joined room or recent public activity. | Before and after a block, mute, hold, appeal or withdrawal, two independent sessions and a signed-out visitor see only eligible posts, replies, counts and preview targets. An empty feed offers a room or champion destination. A failed read shows an unavailable state and allows retry. When a preview ages out, keep the player and draft context intact and explain how to refresh the source. [Feed visibility and navigation](./feed.md) · [Local reproducible walkthrough](./demo.md) |
| **Bound the cost.** Attach from the existing cached match sample. Reuse the normal player refresh and cooldown. Exclude timeline retrieval from feed, search and composition. Add a later timeline on demand only with a bounded per-match request, shared backoff and documented provenance. | The profile-to-preview, publish, hub and feed paths add zero outbound Riot calls for warm match context. A missing context produces a useful recoverable state. A forced refresh can show a cooldown, and a vendor failure can preserve the last known public evidence. Inspect request counts with fixture transport and test a withheld, stale or rate-limited upstream independently of reply reading. [Snapshot resolver](../../src/lib/question-match.ts) · [Riot limits](https://developer.riotgames.com/docs/portal) |

The initial proof is the signed-out reference workflows plus the repository’s local demonstration. Live Riot RSO approval, real email delivery, native app behavior and production write paths are outside those observations.
